| `bulk` | Score many JDs at once and rank them: reads a directory (`--jd-dir`) or explicit files (`--jd-files`), resolves company/role from filenames (`AcmeCorp__Data-Scientist.txt`) or a `--manifest` CSV, scores each with the same matcher as `match`, and prints a ranked table (score, verdict, company, role, top missing must-haves). `--top N`, `--min-score N`, and `--json` for scripting; unreadable files are skipped with a warning. |
| `refreq` | Referral request workflow: track outbound asks (contact, company, role, status `drafted → sent → reminded → connected / declined`), print the ask draft via `followup.referral_ask`, and get nudge reminders for `sent` requests quiet longer than `--days` (default 7) with a check-in draft. Stored as JSON you can inspect. |
| `schedule` | Interview scheduling helper: paste an invite and get dates, times, timezone hints, interviewer names, video links, and duration — with explicit "please confirm" flags for anything ambiguous instead of guesses. Plus a reply draft proposing the 2–3 time slots you supply via `--slots`. Stdlib only. |
| `thanks` | Post-interview thank-you sequencer: per application, one step per interviewer (name, round, draft via `followup.thank_you`, same-evening timing guidance, pending/sent status). `plan` prints every draft; `mark-sent` tracks what's gone out. Stored as JSON keyed by app_id. |
| `offer deadline` | Decision deadlines on offers: an urgency-sorted countdown with exploding-offer flags (fewer than 7 days left), plus a weighted decision framework over comp/growth/team/location/stability with a ranked table and a "what would change my mind" section naming the score bumps that would flip the ranking. Deadlines live in a sidecar file so `offer.py` storage is untouched. |
| `reapproach` | Re-approach watchlist for companies worth retrying after 6-12 months: auto-computed retry dates from last contact (calendar-correct month math), `due` for dates that have arrived with days-overdue, and watching/due/re-approached statuses. |
| `deadlines` | Application deadline countdowns: lists tracked applications with deadlines sorted by urgency (overdue → due ≤3d → due ≤7d → later), with days-remaining per entry; `--days N` filters the window. Set via `track update ID --deadline YYYY-MM-DD`. The dashboard shows the same data as an alerts banner and per-card countdowns on the kanban. |
| kanban (dashboard) | Pipeline kanban view: one column per tracker status with cards showing company, role, days-in-stage, next-action hint, and deadline countdown. Move cards by drag-and-drop or the per-card status dropdown (wired to the existing `update_status` backend); set deadlines from the date picker on each card. |
| `note` | Per-application notes: timestamped entries stored per app_id (`note add` / `note list --app-id`), so interview prep notes and recruiter call logs stay with the application instead of scattered files. |
| `attach` | File attachments per application: copies user files into the git-ignored data dir with sanitized filenames and a 25 MiB per-app cap; metadata (name, size, added date) recorded as JSON. |
| `packet` | Application packet export: one PDF with the tailored resume + cover letter for an application (reuses `tailor` output verbatim, never re-invented), plus an optional references final page only with `--include-references`. Stdlib-only PDF writer. |
| `references` | Reference list management: add/list references (name, relationship, contact) used by the packet's consent-gated references page. |
